# UdayGuruji Kundali

A production-ready Vedic Kundali (birth chart) generator: customers submit birth details, the backend resolves the birth place to coordinates and timezone, calls a Vedic astrology provider, stores the full result in MySQL, and renders a professional multi-page, printable, downloadable Kundali report in English, Hindi, and Marathi. Includes a customer-facing site and an admin dashboard (kundali history/search, brand settings).

## Architecture

```
React + Vite (customer site + admin dashboard, i18n: en/hi/mr)
        |  REST (/api/v1/...)
Node.js + Express
   |- kundali pipeline: geocode -> timezone -> astrology provider -> persist
   |- admin auth (JWT) + RBAC (admin/staff)
   |- PDF generation (Puppeteer renders the print route server-side)
   `- provider adapters (astrology, geocoding, timezone) - isolated & swappable
        |
MySQL (kundalis, charts, planets, dashas, yogas, doshas, ashtakavarga, users, brand settings, audit log)
```

Astrology and geocoding/timezone API credentials live only in the backend's environment and are never sent to the frontend. See `backend/src/providers/` for the adapter interfaces - swapping providers means writing one new class, not touching services or controllers.

## Project layout

```
backend/    Node.js + Express REST API, MySQL access, provider adapters, PDF service
frontend/   React + Vite customer site and admin dashboard
```

## Prerequisites

- Node.js 18+
- MySQL 8+
- API keys:
  - [Free Astrology API](https://freeastrologyapi.com) key (`FREE_ASTROLOGY_API_KEY`)
  - [TimeZoneDB](https://timezonedb.com) free API key (`TIMEZONEDB_API_KEY`)
  - Nominatim (OpenStreetMap) needs no key, but requires a valid contact `User-Agent` per their usage policy (`NOMINATIM_USER_AGENT`)

## Setup

### 1. Backend

```bash
cd backend
npm install
cp .env.example .env   # fill in DB credentials, JWT_SECRET, and the API keys above
npm run migrate         # creates the database (if needed) and applies schema migrations
npm run seed             # creates the initial admin user (SEED_ADMIN_EMAIL / SEED_ADMIN_PASSWORD in .env)
npm run dev               # starts the API on http://localhost:5000
```

### 2. Frontend

```bash
cd frontend
npm install
cp .env.example .env   # set VITE_API_BASE_URL to point at the backend
npm run dev              # starts the site on http://localhost:5173
```

Open http://localhost:5173 for the customer site, and http://localhost:5173/admin/login to sign in with the seeded admin account.

## Testing

```bash
cd backend
npm test
```

Backend tests cover request validation, authentication, and the geocoding/timezone provider adapters (HTTP mocked). Run the frontend manually via `npm run dev` and exercise the golden path (generate a kundali, view the report, print/download PDF, admin login/history/search/brand settings) plus the 320px-1920px responsive range.

## Production build

```bash
cd backend && npm install --omit=dev
cd frontend && npm run build   # outputs frontend/dist - deploy as static files behind the API
```

Set `NODE_ENV=production` and ensure `JWT_SECRET` / `DB_PASSWORD` are set - the backend refuses to start in production without them. See the `hostinger` skill for deployment conventions when deploying to Hostinger Cloud.

## Security notes

- Astrology/geocoding/timezone credentials are backend-only, read via `backend/src/config/env.js`.
- Kundali reports generated by unauthenticated customers are protected by an unguessable per-record access token (not just the sequential numeric ID), so kundali IDs cannot be enumerated to read other customers' birth data.
- Admin/staff routes require a JWT and role check; passwords are bcrypt-hashed.
- All SQL access uses parameterized queries via `mysql2`.
